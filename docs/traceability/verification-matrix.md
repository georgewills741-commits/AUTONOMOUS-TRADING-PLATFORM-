# Verification Matrix

> **Generated** by [`tools/docs/build_index.py`](../../tools/docs/README.md) from the requirement markers of the code, the tests, and the documents, the [requirements registry](../requirements/registry.md), the [System Rules Register](../requirements/system-rules-register.md), the [Stage 1 plan](../roadmap/stage-01-foundation-plan.md)'s section 3, and the [stage record](stage-01-foundation.md)'s checkpoints; do not edit it by hand. The markers and how to write them are described in the [documentation tools](../../tools/docs/README.md). `build_index.py --check-only` fails when this file is out of date, when a marker names an unknown requirement or one that is not approved (ARCH-029, GOV-017), and when a requirement of the plan's section 3.1 has no implementation or no test or check.
>
> **What it connects** (master execution constitution §145; ARCH-031, ARCH-040): requirement, system rule, owning system, interface, implementation, test, verification, and status. The commit of each verification is that of its record, in the [project state](../project-state.md)'s checkpoint log: a generated file cannot hold its own commit. The links of [owner decisions 14](../handoffs/owner-decisions-14-company-grade-order-and-traceability.md)'s §31 chain are reached here and in the registry, without a second registry ([DEC-046](../decisions/DEC-046-preserve-company-grade-order-and-traceability-rules.md), decision 4): the requirement ID (here, linked to its specification); the decision (the registry's Source and Approval columns); the owner and the system (the owning system, the registry's Owner column, repeated here); the implementation, the test, and the verification (here); the roadmap stage (the registry's Default stage, repeated here; the [roadmap](../roadmap/roadmap.md) is authoritative where it places a requirement elsewhere); and the status (here).
>
> **Columns.** *Interface*: the committed contracts (`contracts/`) defined by a package that implements the requirement. *Implementation*: the artifacts whose `Requirements:` marker names it. *Tests and checks*: the test functions whose `pytest.mark.req` marker names it, and the checks that are not pytest tests whose `Verifies:` marker names it. *Verification*: the checkpoint that built each unit the plan assigns to the requirement, and its verification record. *Status*: that of what Stage 1 delivers of the requirement, the second column, not of the whole requirement, which is implemented in full only when each part of it is built, in the stages that build them (the [requirements README](../requirements/README.md), "Status"): VERIFIED when it is implemented and tested and each of those checkpoints passed its three gates; otherwise IMPLEMENTED AND TESTED, with the checkpoint whose gates are pending. A marker added after a checkpoint is checked by the gates of the change that adds it, recorded in its verification record, and the whole stage again by its own gates at its exit (the stage record's X2).
