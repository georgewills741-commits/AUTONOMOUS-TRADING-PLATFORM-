- **Root-cause review after run 2** (DEC-045, decision 7: the blocking count rose, from three to four, two findings reopened C-01, and one was caused by a fix). Cause: run 1's fixes added a handler for each call the reported inputs reached, instead of making the reading of a file one boundary. A file's reading calls several functions on untrusted input, each with its own failures: looking at the file (`stat`, inside `is_file`), reading it, decoding it, parsing it, converting it to its JSON form (`json.dumps`, with its limit on the digits of an integer and its depth), and validating it; the scanner converts each declaration the same way. Fixing call by call left `is_file`'s `stat` and `json.dumps` outside, and the scanner's conversion. Correction: each file's reading (`_read_file`) and each document's reading (`_read_toml`) is one boundary around all its steps, and maps every class of failure that the file or its content can cause (`OSError`; `ValueError`; `RecursionError`) to `ConfigurationError`, with the known cases' messages kept, except the exhaustion of the process's memory by a file too large, which the developer guide states as a limit (run 3's C-18); the scanner's declaration check is the same boundary. Prevention: property tests that any text whatever is read or refused (`test_any_text_is_read_or_refused`) and that the declaration check returns findings for any content and never raises (`test_any_content_is_checked_or_reported`), so that the class is tested, not only the inputs found; each step's own failure is also tested by name, and mutated. As first written, the property tests' examples almost all failed at parsing (run 3's C-16). Their documents are now built from lines of TOML, each with one value that fails a chosen step of the reading, or none, and their reach is measured: their statistics show each step's outcome (an integer too long is one event for the reader and the conversion to JSON, whose refusals have the same text; Gate 3 run 4 showed each reached, by mutations that let only one step's class escape), and the seven mutations that remove a class of failure from the two boundaries are each killed by these two tests alone (check 8).
