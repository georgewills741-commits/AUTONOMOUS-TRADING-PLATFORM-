# System Rules Register

> **Status:** ACTIVE — 2026-09-30, extended 2026-10-01. The canonical System Rules Register required by ARCH-038 (Handoff Part 3 §468). Placement: [DEC-031](../decisions/DEC-031-part-3-reconciliation.md). SR-46, SR-47, and ARCH-042 in SR-09 added by [DEC-033](../decisions/DEC-033-adopt-master-execution-constitution.md).
>
> **Index only (DUP-38).** Each rule's governing wording is its canonical requirement, in the owning specification. The "Rule" column is a short name, never a second copy of the text. When a requirement changes, the rule changes with it. Every rule is **DOCUMENTED — not implemented, not enforced**: nothing is enforced until the owning stage is built and verified.

## How to read this

- **Fields (ARCH-038):** rule ID; rule (short statement); canonical requirements; classification; source; owner; related systems and dependencies; enforcement location; handling on violation (ARCH-039); verification method; status.
- **Classification** is the class of the first-listed canonical requirement.
- **Enforced where / on violation** is where the architecture places the check and what a violation triggers, from the canonical requirements (ARCH-039: reject; block; safe mode; alert; suspend; rollback; human review). "Design review" means the rule is checked when a feature is designed or changed (GOV-002), because it constrains design rather than a runtime event.
- **Verification (planned)** is the kind of evidence expected. The exact method and test are assigned when the owning stage is planned (ARCH-030); none exists yet.
- **Precedence:** when rules conflict, the hierarchy of SR-02 decides. The safety floor (SR-01) is on top.
- System IDs are in the [system registry](../architecture/system-registry.md); requirement IDs in the [registry](registry.md).

## Maintaining the register

- Add a rule when an approved requirement is a behavioral rule the platform must enforce or that constrains every design. Give it the next SR number; never renumber.
- A rule that stops applying is marked DEPRECATED with its replacement, never deleted (GOV-009).
- [`tools/docs/build_index.py`](../../tools/docs/README.md) checks that SR numbers are sequential and unique, that every SR reference elsewhere is defined, and that every requirement ID in the table exists.
