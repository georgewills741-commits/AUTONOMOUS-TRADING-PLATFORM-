## Status labels used throughout

| Label | Meaning |
|---|---|
| ACTIVE | In force: a living document kept current, or a dated record that stays as written after its checkpoint, except for additions its "Later changes" line states (a document label, not GOV-009's feature status) |
| DOCUMENTED | Recorded from a handoff; not implemented, not verified |
| DECIDED | Chosen by a decision record (the [technology stack](architecture/technology-stack.md), DEC-009); applied only as far as an authorized stage builds it |
| APPROVED | A plan approved by the owner (the [Stage 1 plan](roadmap/stage-01-foundation-plan.md), DEC-038); a document label, not GOV-024's feature state |
| FUTURE | Recorded but deliberately not built now (e.g. custody) |
| DEPRECATED / REPLACED | Superseded; the replacement is named |
| ACCEPTED (delegated) | A decision the builder made under an explicit owner instruction; the owner may override it |
| HISTORICAL | Source input kept for traceability; not an active source of truth |
| DRAFT | Unverified work kept so that it is not lost ([owner decisions 15](handoffs/owner-decisions-15-stage-transition-persistence-and-commit-integrity.md), §1): not approved, not authoritative, not verified, not production-ready; it defines nothing and is replaced by the step it serves ([drafts](drafts/README.md)) |
| REFERENCE | Material that records rely on, kept exactly as it was produced: not authoritative, not a source of rules, and not maintained (one of the document classes of [owner decisions 14](handoffs/owner-decisions-14-company-grade-order-and-traceability.md), §6; [mutation checks as run](traceability/stage-01-mutation-checks.md)) |

[Owner decisions 14](handoffs/owner-decisions-14-company-grade-order-and-traceability.md) (§6) asks that every important document be clearly one of eight classes. Here, a document whose banner says HISTORICAL, DRAFT, or REFERENCE is that class, and one labelled DEPRECATED / REPLACED is SUPERSEDED. A file, or the parts of one, that a tool writes says so in its banner: GENERATED (the requirements registry, and parts of the handoff coverage and of the Part 2 and Part 3 reconciliations). Every other document, verification records included, is AUTHORITATIVE for what it holds. No document is a PROPOSAL or ARCHIVED; one would say so in its banner ([owner rule sets reconciliation](traceability/owner-rule-sets-reconciliation.md)).
