## Stage classification and sequence

- **RMP-001** Minimum stage classes · CONFIRMED REQUIREMENT · §95 — At minimum: FOUNDATION; DATA FOUNDATION; CORE TRADING FOUNDATION; DIRECTIONAL TRADING; ARBITRAGE; AI INTELLIGENCE; OPERATIONALIZATION. Exact sequencing must be finalized in the master roadmap after dependency analysis.
- **RMP-002** Sequential stages · CONFIRMED REQUIREMENT · DEC-016 — Stages run sequentially in the order of RMP-001. Every system and capability belongs to exactly one build stage (listed below), and no live trading happens before OPERATIONALIZATION's canary and live-operation items.

## Master roadmap rules (Handoff Part 2)

- **RMP-003** Single master roadmap · CONFIRMED REQUIREMENT · P2§186, P2§335 — Part 1, all prior discussions, and Part 2 feed one master roadmap. There must not be competing master roadmaps. Specialized roadmap views are acceptable, but one dependency-driven roadmap remains authoritative.
- **RMP-004** Deterministic foundation before advanced AI · CONSTRAINT · P2§188, P2§323 — The master roadmap should establish data → normalization → quant → regime → opportunity → risk → capital → execution → reconciliation → portfolio → monitoring before advanced AI functionality.
- **RMP-005** AI infrastructure sequence · CONFIRMED REQUIREMENT · P2§189, P2§324 — AI infrastructure follows deterministic foundations. Potential sequence: AI gateway → structured schemas → tool permissions → Model Router → resource governor → caching → failover → agent architecture → Hallucination Firewall → multi-agent validation → controlled strategy research.
- **RMP-006** Paper and readiness sequence · CONFIRMED REQUIREMENT · P2§190 — Potential sequence: paper executor → simulated capital → continuous paper → expected-vs-actual → evidence accumulation → readiness system → readiness dashboard → canary → production.
- **RMP-007** Arbitrage sequence · CONFIRMED REQUIREMENT · P2§191, P2§325 — Arbitrage follows exchange, economics, capital, risk, and execution foundations: exchange adapters → market data → fee engine → slippage engine → liquidity → capital → risk → execution → reconciliation → cross-exchange → triangular → inventory → rebalancing → expected-vs-actual.
- **RMP-008** Hosting and portability in the roadmap · CONFIRMED REQUIREMENT · P2§192, P2§322 — The master roadmap must include deployment portability: environment abstraction; local deployment; server deployment; portable configuration; database migration; backup/restore; migration package; migration validation; active-instance protection; split-brain prevention; failover where approved; local/server migration testing.
- **RMP-009** Autonomy sequence · CONFIRMED REQUIREMENT · P2§193, P2§326 — Autonomy follows policy, safety, and deterministic foundations: deterministic foundation → policy representation → policy compiler → policy validation → global controller → safe states → autonomous orchestration → AI integration → controlled autonomous improvement.
- **RMP-010** Production hardening before production · CONSTRAINT · P2§194, P2§327 — Before production: security; secrets; monitoring; alerting; reconciliation; backup; restore; disaster recovery; failure testing; performance testing; load testing; chaos testing; deployment; canary; rollback; incident management.
- **RMP-011** Dependency order, not conversation order · CONSTRAINT · P2§195, P2§328 — Features are implemented according to dependencies, not the order in which they appear in conversation. A feature must not be implemented before the infrastructure required to make it safe exists.

How these fit the seven stages ([DEC-024](../decisions/DEC-024-part-2-reconciliation.md)):

- **RMP-004:** already the stage order: DATA and CORE TRADING FOUNDATION come before AI INTELLIGENCE.
- **RMP-005:** runs inside AI INTELLIGENCE.
- **RMP-006:** runs from DIRECTIONAL TRADING (paper executor to Readiness System) to OPERATIONALIZATION (readiness dashboard, canary, production).
- **RMP-007:** spans DATA FOUNDATION (adapters, data, fee and slippage engines), CORE (capital, risk, execution, reconciliation), and ARBITRAGE.
- **RMP-008:** the hosting-abstraction and configuration rules (MIG-004, MIG-010) apply from the first implemented stage; the rest is OPERATIONALIZATION, including failover, which the owner approved (REC-021, REC-023, DEC-030).
- **RMP-009:** the "policy compiler" there is the deterministic compilation of structured policy into enforceable rules, built in CORE with the Policy System. The natural-language front end comes later, in AI INTELLIGENCE (NLP-004). Safe states are built in CORE. The "global controller" is the Policy System, the Risk Engine's emergency controller, and System Health together (ARCH-035).
- **RMP-010:** inside OPERATIONALIZATION, before its canary and live-operation items.

## What Parts 2 and 3 did and did not supply

Part 2 supplied roadmap rules and sequences (RMP-003 to RMP-011) and many capabilities, placed above. It did not supply interface contracts, per-stage entry and exit criteria, or verification methods per requirement. Those are produced when each stage is planned (constitution Rules 75 and 140; ARCH-025, ARCH-030), before that stage's implementation is approved. Every decision DEC-006 to DEC-023 was re-checked against Part 2 in [DEC-024](../decisions/DEC-024-part-2-reconciliation.md); each conflict found is recorded in the [findings register](../conflicts/register.md), not changed silently. Part 3 supplied rules, principles, and capabilities (placed above) and the roadmap areas of RMP-012; like Part 2, it supplied no interface contracts, per-stage entry and exit criteria, or verification methods. Every decision DEC-006 to DEC-030 was re-checked against Part 3 in [DEC-031](../decisions/DEC-031-part-3-reconciliation.md).
